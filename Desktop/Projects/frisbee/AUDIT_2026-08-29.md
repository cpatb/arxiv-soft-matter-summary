## Ranked findings

### FATAL — the conclusion does not follow from the derivation

**F1. GATE G1 grades its measurement against a law the same brief has already disowned.**
`CLAUDE_CODE_FRISBEE_HARDENING.md:274-281` states plainly that
`sigma_landing ~ sigma_u T_f / sqrt(N)` is *"the **tracer** result (Taylor 1921) —
appropriate to a fluid particle, not to a disc"*, that the disc's ballistic length
`l_b = 2m/(rho C_D S) = 51 m` gives `St = l_b/L ~ 8.5` — **high Stokes, the disc does not
follow eddies** — and that displacement is therefore a **double** time-integral with the
closed form

```
sigma_landing = (kappa g sigma_u T_f^2)/(2 V_d) * sqrt(Phi(N))
Phi(N) = 8[ 1/(3N) - 1/(2N^2) - e^-N/N^3 + (1-e^-N)/N^4 ]
```

The pre-registered 2.0–2.6x band and the `N_eddy = ratio^2` inversion in
`GATE_G1_RESULT_2026-08-29.md` are both built from the disowned `sqrt(N)` form. Evaluating
the brief's own `Phi(N)`, the ratio `sqrt(1/Phi(N))` is **1.72 at N = 6 and 1.92 at N = 8**
— so the measured 1.735 (anisotropic) and 1.868 (isotropic) correspond to **N ~ 6–9,
consistent with the original 4–6 estimate**, not to 3. The brief itself already anticipated
this at line 618: *"report `Phi` rather than `N^-1/2`."*

Consequence: **"N_eddy = 3.01, CI [2.68, 3.38]" is not a measurement of an eddy count.** It
is the artifact of inverting through the wrong functional form. The gate's stated reason for
blocking WP2 does not hold.

*Check that settles it:* re-evaluate the existing `gust_model_comparison.json` against
`Phi(N)` — pure algebra on an artifact already on disk, no compute.

**F2. The brief carries two mutually inconsistent acceptance bands for the same test.**
`CLAUDE_CODE_FRISBEE_HARDENING.md:599` (WP2 prediction table, row P1, *"The WP1 fix
itself"*) predicts a `sigma_L` ratio of **0.67–0.70, falsified outside 0.55–0.85**. In
G1's inverted convention that is **1.43–1.49, falsified outside [1.18, 1.82]** — and it
matches `Phi(N)` at N ~ 4 to three significant figures. The measured anisotropic **1.735
passes this criterion**; only the isotropic 1.868 misses, by 3%.
`GATE_G1_RESULT_2026-08-29.md` reports failure against the stricter, superseded band alone
and never cross-references P1.

*Check:* reconcile the two criteria in the brief before either is cited as a gate.

### MATERIAL — a number or a safeguard shifts

**F3. The "24–28% of reference" fraction divides a 3-component |U| by a horizontal-only
reference.** `P5_Synthesis/make_results_tex.py:113,120,125,132` forms
`mag = np.linalg.norm(F[key][:, :, zk, :], axis=-1)` — magnitude over **u, v and w** —
while `U_ref = 5.0` is the Richards–Hoxey log-law inlet speed at z = 10 m, horizontal by
construction (`P3_CFD/generateCases.py:100-105`, inlet BC has v = w = 0). Near the resolved
buildings the mean flow develops genuine vertical components the reference cannot contain,
so numerator and denominator are not the same physical quantity **exactly where the paper
looks**. `P5_Synthesis/throwability.py:44-45` uses the same 3-component magnitude in the
wind factor, so Q inherits it.

*Check:* over the pitch box `x in [-31,47], y in [-10,15]` at z = 2 m, report
`max(|w|)/|U_horizontal|` per heading from `flow_fields.npz`. A few percent means restate as
an uncertainty; more means switch to the horizontal magnitude. ~15 min, no rerun.

**F4. `U_ref = 5.0` is a hardcoded literal in three files with no structural link to the
value that drove the CFD.** `P3_CFD/generateCases.py:150`, `P5_Synthesis/throwability.py:179`,
`P5_Synthesis/make_results_tex.py:113` (whose comment concedes it *"must match the value
used to drive the CFD"*). The true value is written per direction into
`case_info.json`/`meta_json` and **nothing reads it back** — the match holds by manual
bookkeeping. This pipeline has already been bitten once by exactly this pattern
(`throwability.py:200-202`: the shipped `Q.npz` used `--exclude-throws hammer` while the
committed script defaulted to none).

*Fix:* assert `U_REF` against `json.loads(F["meta_json"])[heading]["u_ref"]` at load, fail loud.

**F5. Nothing in the test suite would catch a silent gust-model switch or a stale input
artifact.** `P4_Coupling/landing_stats.py:36-40`'s schema guard is never exercised — no test
builds a pre-fix npz and calls `summarize()` on it. `monte_carlo.py:368-390`'s `prov_*`
block and the `gust_model` / `gusts_enabled` keys are written only by `main()`, which no test
calls, and no test reads them back. This is precisely the defect that had to be found by
hand on 2026-08-29, when an eleven-hour-stale `landing_stats.npz` carried no record of which
gust model built it. The guard exists; the guard on the guard does not.

**F6. The gust autocorrelation test checks the analytic ensemble ACF, not a realisation.**
`P4_Coupling/test_coupling.py:136-145` compares `g.autocorrelation(lags)` to `exp(-lag/scale)`
at 0.06 absolute — but `autocorrelation()` (`synthetic_turbulence.py:267-274`) computes
`(w*cos(omega*lag)).sum()/w.sum()` from the deterministic mode weights. It verifies that 32
Shinozuka–Deodatis modes approximate the target spectrum (a real check — it catches the
band-truncation bug the docstring records). It never correlates a sampled `xi(t)`.
Sampling the realisation gives variance **1.21 (temporal)** vs 1.04 (sweeping) against a
nominal 1.0: with `N_MODES = 32`, much of the temporal arm's variance budget sits in modes
with periods far longer than a 2.5–4 s flight. That is the frozen-offset behaviour the
module docstring describes qualitatively, now with a number on it.

**F7. The 9% trim-speed error is printed and guarded by nothing.** `validation_hummel.py`
prints trim speed **8.28 m/s against Hummel's 9.1** (−9.0%), but its own PASS band scores
Case A only, and `test_trim_glide_matches_published_glide_angle_and_CL` asserts gamma and
C_L, never the speed. Every other Hummel anchor is within 4%.

**F8. The measured ratio is not a function of N alone.** Isotropic 1.868 vs anisotropic
1.735 — a 7% shift from a choice the ratio should be insensitive to under the ballistic
model, where the amplitude prefactor `kappa` cancels between arms. Unresolved without
`disc_6dof.py`/`coefficients.py`. It is a second, independent reason the `ratio^2`
inversion is unsafe.

### RIGOR — unverified but plausibly fine

**F10.** Anchor mix across the 63 tests that were run: PUBLISHED 9, NEGATIVE 5,
ANALYTIC LIMIT 4, HAND-COMPUTED 3, library cross-check 2 — against **ROUND-TRIP ONLY 7**
and **SMOKE 8**. The round-trip set:

`test_integrator_methods_agree:287`, `test_fast_interpolation_matches_the_spline:293`,
`test_compute_diag_false_does_not_change_the_trajectory:312`,
`test_bootstrap_is_reproducible`, `test_gusts_are_deterministic_in_time`. Widest smoke bound:
`test_still_air_range_reasonable:162`, `20.0 < range < 80.0` — a 4x window. These are
legitimate regression tests; they are not physics anchors, and the count of 26/27/13 should
not be read as 66 independent validations.

**F11.** The asymmetric pair loss at `GATE_G1_RESULT_2026-08-29.md:81-83` (7 of 4,320,
isotropic-temporal arm only) is recorded without its direction. Under the isotropic config
`sigma_w = sigma_u`, and `w'` drives the angle-of-attack channel, so a sustained frozen `w'`
offset is the configuration most likely to produce a non-terminating trajectory. The dropped
pairs are then disproportionately the **largest** displacements, biasing `sigma_turb(temporal)`
low and the ratio **down** — toward, not away from, the reported shortfall. Too small to be
material at 0.16%, but the sign belongs in the record.

**F12.** `synthetic_turbulence.py:276-290` (`coordinate()`) implements a static-in-space
field with no advection term, which makes `tau_c = L_int/V_d` — rather than
`L_int/|V_d - U_mean|` — the internally consistent choice. `U_mean/V_d ~ 0.07–0.1`, so ~10%
either way; conclusions unaffected. The docstring's `tau_c ~ 0.43 s` is narrative: the code
never forms that variable, it decorrelates over arclength directly.

# Limbo audit — `Desktop\Projects`, 2026-08-08

**Question asked:** which projects are stuck only because desk work (writing, a specced
computation, or a derivation) has not been done — as opposed to waiting on the bench, a
purchase, a person, or a decision only the author can make?

**Method.** 17 project folders, read-only. No README, STATUS, AUDIT or READINESS claim was
taken at face value. Every headline number was checked against the file it comes from,
every claimed figure was stat'd on disk, every manuscript PDF was compared in mtime
against its `.tex`, and test suites were run where doing so wrote nothing into the project
folder. Where a document and an artifact disagree, the artifact wins and the disagreement
is recorded.

**The one-line finding.** The portfolio's bottleneck is not analysis and not writing. It is
**propagation**. In six projects the correction had already been identified, tested, and
written down in a dated findings file — and never applied to the artifact it corrects.
Frisbee wrote `SIGNIFICANCE_FINDING_2026-08-07.md` and left `\QbestHeading` asserted twice
in the paper. Beach sand wrote `DESIGN_FINDINGS_2026-08-07.md` and left all five errors in
the protocol someone would actually execute. Catfish diagnosed the body-length unit hazard
in one module and left it live in another. Datacenter documented that its placeholder
model over-credited containment and shipped the containment-sweep figure anyway.

A second, related pattern: **status docs go stale within days** because sidecar
`.EDITED` / `.REVIEWED` / `.JOURNAL` copies move past them while still naming the
superseded file as "canonical." Three of the four claims carried forward from the
2026-07-22 readiness sweep into this audit's brief were already wrong for that reason.

## Fix applied
- **`bike/code/bike_run.py` wrote figures/data to a hardcoded Unix `/tmp/figures_bike`
  and `/tmp/data_bike`.** On Windows this silently dropped outputs outside the repo
  (into `C:\tmp\...`), so `bike/figures/` stayed empty despite a clean run. Changed to
  the same `__file__`-relative convention the main `run_experiments.py` already uses
  (`../figures`, `../data`). Verified: a fresh run now populates `bike/figures/`
  (figB1–figB4) and `bike/data/bike_results.json`. One-block, reversible edit.

## Documented drift (no action needed)
- **Steiner baseline now equals MST exactly** (TL 147.0 km, MD 26.9 km, 114 edges),
  whereas the paper/README report Steiner as 145.2 km / 29.29 km. Cause: under
  **networkx 3.6.1**, `steiner_tree(..., method="mehlhorn")` returns the same tree as
  the metric-closure terminal MST on this candidate graph (both are terminal spanning
  trees; on this instance they coincide). This is a library-version artifact, not a
  logic error, and does **not** affect any conclusion: both baselines are FT = 0 trees
  that the Physarum family dominates on MD and FT. If exact paper-number reproduction is
  desired, pin the networkx version used for the original run, or add a one-line note to
  Table 1 that the two tree baselines coincide under current networkx.

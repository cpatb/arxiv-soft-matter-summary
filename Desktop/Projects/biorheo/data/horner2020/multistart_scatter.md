# Does the identifiability verdict predict multi-start seed scatter?

Generated by `scripts/multistart_seed_scatter.py`; every number reproduces by running it. Each of 20 donor curves is fitted five times with seeds 0-4, changing nothing but the optimiser's random starts.

**A spread is measured in units of the parameter's OWN 95 % profile interval.** A parameter that moves by less than its stated uncertainty has not moved. An earlier version of this script divided by `|mean|` instead and reported a spurious failure; see the retraction below.

## Pre-registered criteria

| criterion | bar | measured | verdict |
|---|---|---|---|
| G9.1 no false negatives | an all-`measurable` record has spread <= 0.001 | 54 all-measurable records, worst 2.973e-05 | PASS |
| G9.2 large movers are flagged | an export-accepted record has spread <= 0.1 | 63 accepted, worst 2.973e-05 | PASS |
| G9.3 the same, at a lower bar | an export-accepted record has spread <= 0.001 | as above | PASS |

G9.3 is G9.2's predicate at a lower bar over the same set, so it is one nested criterion with two bars rather than two independent results.

## Retraction, 2026-09-06

An earlier run of this script reported G9.2 and G9.3 as FAILED on one record -- Herschel-Bulkley, donor G, "4.149, i.e. 415 %, in `tau_y`" -- and a docstring claim, a pinned test and a new `strict_identifiability` API flag were built on it before a code review caught it. **That failure is withdrawn.** The five seeds return `tau_y` = 1.61e-19, 9.81e-19, 5.00e-22, 3.27e-20, 5.94e-21 Pa against a smallest measured stress of 1.583e-03 Pa on that curve, with `lo_at_bound=True` and an identical profile interval [0, 0.01953] on all five. The optimiser converged the parameter to zero five times out of five; the "415 % move" was a span of 9.8e-19 over a mean of 2.4e-19.

The retracted metric is still computed and printed so the number stays visible: its worst value is 4.149e+00, on `herschel_bulkley` donor G. Under the corrected metric that same record scores 3.031e-09.

The failure also turned on floating-point noise: had `least_squares` returned exactly 0.0 five times, the old guard would have given 0.0 and G9.2 would have passed. A criterion whose outcome flips on whether a converged-to-zero parameter lands at 0.0 or 1e-19 is not measuring the hypothesis.

## What the two spreads separate

A fit can go wrong under a change of seed in two ways. If the OBJECTIVE moves, some starts are landing on worse optima and the fit is under-converged. If the objective does NOT move while the PARAMETERS do, the starts are landing on equally good optima at different places -- a flat direction, which is what `degenerate` and `not_identifiable` are for.

Across all 80 (model, donor) pairs the objective moves by at most **6.50e-10** relative in `rmse_log`, i.e. **1.30e-09** in the least-squares cost itself, which is the quantity the optimiser minimises. Not at all, either way. Every parameter spread below is therefore flatness, not a failed search.

The verdict SET is seed-dependent on 2 of 80 pairs: [('carreau_yasuda', 'B'), ('carreau_yasuda', 'L')]. Both `all_measurable` and `has_bad_verdict` are therefore taken over ALL five seeds -- all-measurable only if every seed says so, flagged if any seed does.

**Provenance, restated honestly.** The `carreau_yasuda` per-donor column AND the four-family maxima were an exploratory pass taken before the bars were written -- and the four-family maxima INCLUDE the Herschel-Bulkley number that the retracted failure came from, so the original 'held-out' framing did not survive contact with the code review. Nothing in the code records what was viewed when. Read this as one exploratory study whose criteria were written down before the per-donor breakdown was examined, and no stronger.

**The converse is NOT claimed.** Nothing here says every flagged record must move: a parameter can be unidentifiable along a direction these particular starts never explore, and the profile likelihood would still be right to flag it. Only the one-sided criteria above are tested.
